## 已明确的要求

1. 需要 AI 的语义理解、表格结构识别、口径判断、文本复核和终审，由正在驱动该技能的当前 agent 及其模型承担；不能把固定模型厂商作为主控或默认调用另外的模型接口。
2. 技能启动时先询问当前模型的上下文容量，至少区分 1M 与 128K；按用户选择执行对应流程，不根据模型名称臆测容量。
3. 128K 流程须节省上下文并支持大报告完整复核；优化不得缩减已选检查深度、遗漏科目或把未检查记成通过。
4. 代码与业务同时复核，不只改 DeepSeek 开关或替换文案。
5. 所有数值运算继续由确定性代码执行，当前 agent 负责判断取数范围、来源、期间和口径。

## 用户与使用场景

使用者是注册会计师，通过本机 AI agent 调用技能复核审计报告。目标资料包括既有技能宣称支持的 Word、Excel、PDF、扫描图片、分体式和合体式报告，以及只有附注的资料。分别核查合并及母公司、本期及上期，不混淆其口径。

## 功能范围

1. 技能说明、全部现有源代码及参考规则：检查真实调用链、依赖、默认行为、失败处理和文档一致性。建立逐文件审查记录，不能以抽读替代全量审查。
2. 解析与取数：文档和表格完整性、复杂表头、续表、同名表格、单元格来源、金额单位、空白与零、负号、重复项目、OCR 可靠性、缓存适用性。
3. 算术与业务：四张报表内部及相互关系、表注勾稽、附注内变动关系、横加竖加、权益矩阵、合并与母公司区分、期间匹配、净额与余额、受限资金与现金等价物、容差与四舍五入解释；逐项检查业务规则是否正确且与程序执行一致。
4. 文本及格式：主体、日期、期间、单位、编号、错别字、前后矛盾，以及来源定位是否可供审计人员核验。
5. 结论与交付：明确区分已验证通过、确认错误、待核实、未执行、不适用；检查终审是否实际落实、是否发生误删问题或虚假通过，Excel 与 Markdown 的统计及明细是否一致。
6. AI 与上下文：当前 agent 承担语义工作的完整流程；启动询问上下文档位；128K 条件下的资料分批读取、进度记录、恢复及跨批勾稽；1M 与 128K 对同一检查范围保持同等验收标准。
7. 文件和外部服务保护：检查源报告是否只读，既有输出是否会误覆盖，以及是否存在未经明确授权就上传文件或读取密钥、发起外部模型请求的路径。

## 明确不做的内容

- 不默认新增金融等行业完整专用体系；现有规则中涉及的业务表述仍须核查并列明适用限制。
- 不把本轮技能审查冒充对某个客户报告的审计结论。

1. 对全部源代码、技能说明、参考规则建立覆盖记录；发现逐项包含位置、现象、影响、复现或业务依据、整改建议及验证状态。

3. 启动询问上下文档位；128K 与 1M 在相同资料及范围下，得到一致的应检对象、确定性金额和结论分类，不允许通过截断或跳过降低工作量。
4. 算术验证覆盖负数、括号负数、单位、空白、零、非法值、精度及容差边界；错误不能静默变成正常金额。
5. 合并与母公司、本期与上期、原值与净值、金额与比例分开核对；无法识别、资料缺失或未执行必须留痕。
6. 终审结论有回原文依据；未经检查不得计入通过；确认误报也保留可追溯的处置依据。
7. 真实完成所有批准的整改与回归验证后才称整改完成；只完成审查时明确尚未整改。
