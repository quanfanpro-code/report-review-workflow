# 📋 财务报告复核工作流

> 一句话：把一份财务报告或审计报告丢给它，它会像请了一整个专家团队那样，从头到尾帮你查一遍，最后交给你一份"问题清单"和一份"改好的报告"。

---

## 🎯 这是什么

这是一个**报告复核技能包**，专门对付财务报告、审计报告、专项报告的全面检查。

你可以把它想象成一个"复核工作室"。它自己不带脑子——它是给人工智能助手用的说明书。人工智能助手读了它，就知道该按什么顺序干活、每一步查什么、查出问题怎么记、最后怎么交活。

**它最大的特点是"自包含"**：干活需要的全部资料都装在这个包里，不依赖外面任何其他工具或技能包。下载走、换台电脑、断网，都不影响使用。

### 🌟 它能查出什么

- 📊 **数字对不对**：报告里的数字和你给的权威资料（比如财务报表、台账）对不对得上，期初期末接不接得上
- 🧠 **逻辑通不通**：业务描述和数字是不是一回事，差异有没有追根因，而不是一句"差异较小"糊弄过去
- 📖 **准则合规吗**：关联交易、坏账计提、资产划转这些敏感事项，按会计准则和监管要求处理得对不对
- ⚠️ **资产有没有雷**：大额挂账、异常账龄、隐性负债这类资产质量风险有没有被揭示
- ✍️ **文字顺不顺**：错别字、病句、专业术语不规范，还有最烦人的"AI 腔"（空话、套话、模板句）——这些它都揪
- 📐 **排版规范吗**：报告文号、签章、表格格式这些形式要件齐不齐

## 🛠 使用方式

### 第一步：准备材料

把两样东西准备好：

1. **要检查的报告**：财务报告、审计报告或专项报告，Word、PDF 都行
2. **权威基准资料**：用来核对数字的"标准答案"，比如已审财务报表、台账明细、上期报告等

### 第二步：开口触发

在支持技能的智能助手（比如 WorkBuddy）里，用下面任意一句话就能启动：

- "复核报告"
- "审报告"
- "全面复核"

### 第三步：回答一个问题

启动后它只会问你**一个问题**："哪些资料作为权威基准？待复核报告应以什么为依据来核对？"

你指认一下哪个文件是"标准答案"就行。其他的（比如问题分几级、出什么形式的结果）它都有默认设定，不用你操心。

### 第四步：中途把关

正式开查之后，它会在几个关键位置停下来让你过目：

1. **开查前**：让你确认检查范围和交付物，防止白忙活
2. **数字核对完**：把核对范围和发现的差异记录在案，然后继续（不会反复打断你）
3. **前五步查完**：把发现汇总给你看，你决定要不要继续查文字
4. **出报告前**：和你确认输出格式和问题分级

### 第五步：收活

最后你会拿到两样东西：**问题清单**和**修改版报告**。不满意可以让它继续深挖，满意就收工。

## 🔄 运行逻辑

整个流程是一条固定的流水线，一共七步，每一步都有专门的"参考资料"随包携带，不靠人工智能凭记忆瞎猜：

**第 1 步 · 深度阅读** 📖
先把报告和背景资料从头读一遍，提取关键数字，建一张"数据对照表"。同时判断这份报告是"正式稿"还是"草稿"——这很重要，草稿没文号没签章是正常的，正式稿缺了就是问题。

**第 2 步 · 数字比对** 🔢
拿你指定的权威资料和报告逐个数字对。两条路线：一条查"期初衔接"（上期期末和本期期初对不对得上），一条查"同口径验证"（同一期间的数字对不对得上）。每个数字都留痕：在哪个文件、哪个位置、原值多少、差额多少。算术全部由包内自带的计算脚本用精确小数运算，不心算、不毛估。最后顺带查关键数字有没有标注来源。

**第 3 步 · 逻辑审查（田川视角）** 🧠
用一套资深审计经理的思维框架来查：业务和财务对不对得上、底稿是不是从面到点层层展开、发现差异有没有追根因、报表之间的勾稽关系、程序有没有随风险收口、每部分说的是否扣题。

**第 4 步 · 准则审查（陈奕蔚视角）** 📖
用一位深耕会计准则二十余年的专家的思维框架来查：法律形式和经济实质是否一致、关联交易价格是否公允、是否符合监管指引、有没有提前确认收益的倾向。重点盯关联方披露、资产划转依据、坏账计提、会计政策附注。

**第 5 步 · 资产质量检查** ⚠️
查大额异常资产、隐性负债、对单一客户或关联方的依赖、风险揭示够不够。**请注意**：这一步原本还有一个私募尽调视角，但因为那个视角的版权不允许公开分发，本包没有收录它。这一步只做降级的人工粗查，检查记录里会如实标注"该视角未整合"，不冒充尽调深度。

**第 6 步 · 文字质量审查** ✍️
三套规范叠加使用：写作规范（错别字、病句、标点、专业术语）＋ 去 AI 味（删空话、合并重复、打散模板句式）＋ 活人感（把机构腔、口号腔、模型腔改写成一个见过事、查过材料的人在说话）。

**第 7 步 · 汇总排版** 📐
把前面所有发现汇总成问题清单，再按事务所排版标准查文号、签章、表格格式、日期关系，最后输出成品。

### 🛡 出错怎么办

每种意外情况都预先写好了应对办法，格式是"什么情况 → 先怎么救 → 救不了怎么办"：

- 包里文件缺了：先看是不是被移动改名，能恢复就恢复；恢复不了就明确报错停止，绝不硬着头皮编
- 数字对不上：完整记录差异继续查，不按比例"忽略小差异"
- 缺基准资料：标注"无法比对"，不猜数字
- 问题太多（超过 30 条）：先给你最要命的 20 条，问你要不要继续看细节

## 📥 输入要求

启动时需要你提供这些东西：

| 材料 | 必要性 | 说明 |
|---|---|---|
| 📄 待复核报告 | **必须** | 财务报告、审计报告或专项报告，Word、PDF 格式均可 |
| 📚 权威基准资料 | **必须** | 用来核对数字的依据，比如已审财务报表、台账明细、上期报告。哪份算数由你指定 |
| 📝 报告状态说明 | 建议告知 | 这份是正式稿还是草稿？草稿可以不纠结文号和签章 |
| 🎯 复核重点（可选） | 可选 | 如果只关心某几个方面，比如"重点查关联方披露"，可以说明 |

**小提示**：资料给得越全，查得越细。如果只给报告不给基准资料，第二步的数字比对就只能标注"缺少基准来源"了。

## 📤 输出内容

全部查完后交付两样核心成果，外加过程留痕：

### 📋 问题清单

每个问题都是一条完整记录：

- **位置**：问题在报告的哪里（哪一节、哪一张表）
- **原文**：报告里原来是怎么写的
- **问题**：毛病出在哪
- **建议**：怎么改
- **来源**：哪个审查步骤发现的
- **严重程度**：三档分级——**致命**（必须改，不然报告不能出）／**重要**（应当改，影响质量）／**细节**（改了更好，锦上添花）

问题超过 30 条时，先出前 20 条致命和重要问题，问你要不要继续展开细节，不会一股脑砸给你。

### 📝 修改版报告

按问题清单修订后的报告成品。

### 📎 过程留痕

- 数据一致性对照表（每个数字核对的双方位置、原值、差额）
- 各审查步骤的独立中间结论（各视角分开记录，不混在一起说糊涂话）

## 📦 这个包里装了什么

为了做到"自包含"，本包把七个专业组件完整装在了一起：

| 组件 | 干什么用 |
|---|---|
| 🔢 数据核对组件 | 第二步的数字比对能力，自带精确计算脚本和 126 项自动化测试 |
| 🧠 田川视角 | 第三步的审计逻辑审查框架 |
| 📖 陈奕蔚视角 | 第四步的会计准则审查框架 |
| ✍️ 写作规范 | 第六步的错别字、病句、术语规范 |
| 🌿 去 AI 味规范 | 第六步的空话、套话、模板句清理规范 |
| 💬 活人感写作规范 | 第六步的机构腔、模型腔改写规范 |
| 📐 华信排版标准 | 第七步的事务所排版格式标准（经权利人授权收录） |

每个组件都保留了原始许可声明。组件的来源、同步日期、许可信息记录在包内的来源台账文件里，上游更新后按台账手动同步即可。

## ⚠️ 注意事项

1. **第五步是降级版**：私募尽调视角因版权限制未收录（详见包内决策记录），第五步只做人工粗查，别拿它当完整尽调使。
2. **不替代专业判断**：它帮你找问题、给建议，但改不改、怎么改，最终由你（或你的注册会计师）拍板。
3. **数字核对依赖基准资料**：基准资料给错了，核对结论也跟着错——"标准答案"的选择权在你手里。
4. **测试产物会自动忽略**：包内自带的自动化测试运行时会生成临时文件，已配置为自动忽略，不会污染仓库。
