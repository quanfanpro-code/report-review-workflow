# 事务所标准 Word 格式（OfficeCLI 版）

本规范用于四川华信(集团)会计师事务所出具的审计报告、财务报表、附注等正式 Word 文档。排版规则与原 .NET 版完全同步，执行引擎替换为 OfficeCLI + Python 编排脚本。

### 排版执行顺序（数据来源：§一~§九）

```
1. 页面设置（§一）→ 2. 字体（§二~§三）→ 3. 段落格式（§三）→ 4. 表格（§四）→ 5. 页眉页脚（§五）→ 6. 落款（§六）→ 7. 封面（§七）→ 8. 全局清洗（§八）
```

各步骤参数见对应章节的速查表（§九）。

## 前置条件

### 1. OfficeCLI（必需）
本 skill 不内置 OfficeCLI，需要单独安装。脚本通过环境变量 `OFFICECLI` → 系统 PATH → 默认路径 `%LOCALAPPDATA%\OfficeCLI\officecli.exe` 三级查找。

**下载与安装**（任选一种）：
```bash
# 方式一：一键脚本
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/install.sh | bash
# Windows (PowerShell)
irm https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/install.ps1 | iex

# 方式二：包管理器
brew install officecli                  # Homebrew（macOS / Linux）
npm install -g @officecli/officecli     # npm 全平台

# 方式三：手动下载
# 从 https://github.com/iOfficeAI/OfficeCLI/releases 下载对应平台二进制
# Windows 推荐放置位置：C:\Users\<用户名>\AppData\Local\OfficeCLI\officecli.exe
```

**验证安装**：
```bash
officecli --version
```
预期输出形如 `OfficeCLI 1.0.129 ...`。

若 `officecli` 装在非默认位置，可通过设置 `OFFICECLI` 环境变量指定：
```bash
# Windows (PowerShell)
$env:OFFICECLI = "D:\tools\officecli\officecli.exe"
# Linux / macOS
export OFFICECLI=/opt/officecli/officecli
```

### 2. Python 3
脚本使用标准库（subprocess、json、re、shutil、os），无第三方依赖。任何 3.x 版本均可，推荐 3.10+。

**验证**：终端执行 `python --version` 可见版本即可。

### 3. 权限
- 对目标 docx 文件有读写权限
- 对输出目录有写入权限
- 不需要安装 Microsoft Office / WPS（OfficeCLI 自带渲染引擎）

## 三、正文段落层级与格式

## 四、表格格式

### 4.1 表格整体
- 100% 页面宽度
- 上/下边框：黑色粗实线 0.75pt，左/右边框：无
- 内部横/竖线：黑色虚线 0.75pt

### 4.2 首行
- 标记为标题行（跨页重复）
- 所有文字居中

### 4.3 单元格对齐

| 位置 | 对齐 |
|---|---|
| 首行 | 居中 |
| 非首行+首列+正整数字符串 | 左对齐 |
| 非首行+首列+其他 | 左对齐 |
| 非首行+非首列+纯数字 | 右对齐 |
| 非首行+非首列+非数字 | 居中 |

### 4.4 数值格式化
千分位+两位小数；负数取正后加负号；零值和单独横杠清空；百分比保留两位小数。

### 4.5 单元格排版
字号小四 12pt、单倍行距、段前后 0、垂直居中、上下内边距 0、无首行缩进、无加粗/斜体/下划线、字符间距紧缩 1 磅（-20 缇）。

## 五、页眉页脚

### 页眉
五号 10.5pt、左对齐、底部黑色单实线 0.75pt 距文字 1pt。

### 页脚
五号 10.5pt、居中、PAGE 域自动页码。有封面时正文第一页从 1 开始。

## 六、落款区

### 定位
按顺序找：`四川华信(集团)会计师事务所`（兼容全角/半角括号）→ `中国·成都` → 日期正则匹配 → 区间内至少 2 行"中国注册会计师"。

### 排版
小四 12pt、固定 42 磅行距（840 缇）、段前后无。

### 左侧三行台阶
| 行序 | 首行缩进 |
|---|---|
| 第 1 行（事务所名） | 0 |
| 第 2 行（特殊普通合伙） | 480 缇 |
| 第 3 行（中国·成都） | 960 缇 |

### 注册会计师签名行（本版新增）
段落插入右对齐制表位 7200 缇（约 12.7cm）：
```xml
<w:tabs><w:tab w:val="right" w:pos="7200"/></w:tabs>
```
通过 `raw-set` 写入 `//w:p[w:r/w:t[contains(.,'中国注册会计师')]]/w:pPr`。

### 日期行
右对齐。

## 七、封面处理
扫描前 60 个元素，表格内同时含"会计师事务所""地址""电话""传真"→ 封面页；仅调页边距（下边距 2.2cm），不动内容。

## 八、全局格式清洗
字符缩放→100%、自适应宽度→移除、字符间距→移除、上下标→移除、非法下划线→移除、自动编号后缀 Tab→清除。


## 十三、失败模式与 Fallback

| 步骤/场景 | 失败模式 | 可能原因 | Fallback 路径 |
|-----------|---------|---------|--------------|
| OfficeCLI 调用 | `officecli --version` 失败 | OfficeCLI 未安装或不在 PATH | 提示用户安装：`irm https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/install.ps1 \| iex`；或手动指定 `OFFICECLI` 环境变量 |
| OfficeCLI 调用 | 版本不兼容 | 安装的 OfficeCLI 版本低于支持规范的版本 | 重新运行安装脚本更新到最新版：`irm https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/install.ps1 \| iex`（PowerShell） |
| 排版执行 | 输出 docx 未生成 | OfficeCLI 执行超时或被杀进程 | 检查输出目录权限；增大超时时间（默认 60s → 120s）；手动执行 `officecli apply <rules>` 单步排查 |
| 排版执行 | 排版后格式不符合预期 | 正则规则未覆盖特殊段落或表格结构 | 输出排版日志中的未匹配段落列表；用调试模式 `--debug` 运行查看每一步的排版决策 |
| 字体处理 | 文档中的字体未正确设置 | 目标系统缺少指定字体（宋体/Times New Roman） | 检查系统字体 `fc-list :lang=zh`（Linux）或 `Get-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts'`（Windows）；提示用户安装缺失字体 |
| 字体处理 | 西文字体回退失败 | 设备没有 Times New Roman | 自动回退到 Serif 类默认字体 |
| 表格排版 | 表格过多导致排版超时 | 文档中大量表格，逐表处理耗时过长 | 启用快速模式，仅检测首行/边框/对齐，跳过逐单元格精细化 |
| 表格排版 | 单元格数值格式化错误 | 千分位/负数/百分比规则误匹配 | 回退到不格式化数值只保留原样；输出告警供人工校验 |
| 表格排版 | 首行标记失败 | 表格结构不符合预期（合并单元格等） | 跳过该表格的"跨页重复标题行"设置，仅做边框和对齐 |
| 页眉页脚 | 页眉页脚未正确设置 | 文档分节符导致规则作用于错误节 | 遍历所有节分别设置页眉页脚 |
| 落款区识别 | CPA 签章行定位失败 | 落款区格式异常（如缺少"中国注册会计师"字样） | 退化为手动制表位：在落款区全部段落上设置右对齐制表位，不对具体行进行区分 |
| 封面识别 | 封面判定错误 | 封面页表格结构不符合预设模板 | 退化为调前 60 段落的下边距而不做精确封面识别 |
| 全局清洗 | 字符缩放/自适应移除破坏特殊排版 | 文档中存在有意使用的字符间距效果 | 不做全局清洗，改为只清洗明确有问题的段落 |

## 十四、检查点设计

| # | 🔴 检查点 | 触发时机 | 确认内容 | 默认操作 |
|---|---------|---------|---------|---------|
| 1 | OfficeCLI 可用性检查 | 首次排版前 | 确认 `officecli --version` 返回正常，引擎可用 | 自动检查，失败时提示安装 |
| 2 | 输入文件确认 | 读取输入 docx 后 | 确认文件路径存在、格式正确（非加密/损坏） | 自动检查，异常时终止并提示 |
| 3 | 输出路径确认 | 准备写入前 | 确认输出目录存在且有写入权限，原文件不被覆盖 | 自动创建输出目录 |
| 4 | 排版结果预览 | 排版完成后 | 展示排版统计（处理了多少段落/表格/页眉），询问是否需要人工校验 | 自动展示统计，等待用户确认是否满意 |
| 5 | 大文档超时预警 | 检测到文档页数 > 100 或表格 > 30 时 | 提示用户文档较大，排版可能耗时较长 | 自动启用快速模式并告知用户 |
| 6 | 字体缺失告警 | 检测到目标字体在系统中不存在 | 列出缺失字体，提示用户安装或指定替代字体 | 列出缺失列表，等待用户确认是否继续 |
| 7 | 落款区检查 | 落款区排版后 | 确认 CPA 签章行和日期行对齐正确 | 自动检查，异常时输出告警 |

## 十五、反例黑名单

| 反模式 | 问题 | 正确做法 |
|-------|------|---------|
| 直接用 OpenXML SDK 操作 docx | 脱离本 skill 规范执行引擎，产生不一致结果 | 统一通过 OfficeCLI + Python 编排脚本排版 |
| 手动修改 docx 里已排好的内容后再重新排版 | 手动修改被覆盖，排版规则第二次执行可能不幂等 | 排好版后只做增量调整，不重新全量排版 |
| 对封面和内文用同一套页边距规则 | 封面下边距要求 2.2cm 而正文要求 3.0cm | 封面页单独设置下边距 1247 缇 |
| 对所有表格统一采用实线边框 | 表格内部横竖线应为虚线，只有上下边框是实线 | 上/下边框黑色粗实线 0.75pt，内线黑色虚线 0.75pt |
| 首行缩进用空格模拟 | 空格在不同字体下宽度不一致 | 用段落格式的 `firstLine` 属性，首行缩进 480 缇（2 字符） |
| 用全角空格做对齐 | 全角空格宽度因字体而异 | 用制表位（tab stop）实现右对齐，CPA 签章行设 7200 缇 |
| 一次排版后不检查直接交付 | 可能存在落款区错位、表格断页等视觉问题 | 排版后必须检查：页眉页脚、表格样式、落款区对齐、分节情况 |
| 用 `sed` / 字符串替换直接在 XML 里改 docx | 破坏 OPC 包结构导致文件损坏 | 始终使用 OfficeCLI 或 python-docx 操作 |
